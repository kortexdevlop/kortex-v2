# 0026 — Nœud HTTP, secrets d'appareil et connecteurs déclaratifs
**Statut** : accepté (2026-10-19), demande de l'utilisateur (étapes 3 et 4 : nœud HTTP, connecteurs de base). S'appuie sur ADR 0025 (proxy) et sur le contrat de ports de `kortex-workflow`.
**Décision** :
- **Nœud HTTP** (`Logic`, op `http`) : méthode GET/POST/PUT/PATCH/DELETE, adresse, en-têtes, corps, « échouer sur erreur HTTP » ; entrées optionnelles `body` et `url`, sorties `text` et `status`. Le moteur produit un job `flow.http` ; l'hôte l'exécute : navigateur par `POST /v1/proxy` (session de compte requise), ordinateur par une requête native (`native::http_once`, redirections suivies à la main, GET seulement, trois au plus, chaque saut revalidé). La politique (HTTPS, port 443, pas d'identifiants dans l'URL, nom DNS public, en-têtes autorisés) est **pure** (`kortex_workflow::http`), appliquée avant toute requête native, à la validation du workflow et miroir de celle du proxy : un workflow importé ne peut atteindre ni réseau privé ni service interne.
- **Secrets** : `{secret:NOM}` dans l'adresse, les en-têtes ou le corps *écrits par l'utilisateur* ; la valeur vit sur l'appareil (trousseau du système sur ordinateur, stockage local du profil dans le navigateur) et n'entre jamais dans le workflow, son export ou le texte venant d'un autre nœud (une valeur de donnée qui contient `{secret:X}` reste du texte).
- **Connecteurs** : contrat `apps/flow/connectors/<nom>/connector.toml` (schéma 1) : actions = requêtes HTTP à gabarits (`{param}`, `{param|json}`, `{param|url}`, `{secret:NOM}`), paramètres FR/EN. Chaque action est un outil du catalogue Flow `connector.<id>.<action>` (une entrée texte optionnelle par paramètre, sorties `text` et `status`), exécuté par le même code que le nœud HTTP, donc avec la même politique. Les secrets du gabarit sont résolus **avant** l'insertion des valeurs. Livrés : Webhook (envoyer du JSON, lire une adresse), Telegram (envoyer un message), Discord (poster par webhook), GitHub (lire un dépôt, créer un ticket).
**Conséquences** : aucun jeton n'est envoyé à nos serveurs hors du transit par le proxy (il ne journalise pas et ne stocke rien) ; OAuth (ADR 0025) n'est pas encore branché sur l'interface, les jetons s'enregistrent à la main comme secrets ; pas de déclencheurs ; le proxy web impose un compte connecté.
**Alternatives** : connecteurs en code Rust par service (écarté : contrat déclaratif plus sûr et extensible) ; secrets dans le workflow (écarté : fuite à l'export).
