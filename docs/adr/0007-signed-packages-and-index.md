# 0007 — Paquets desktop, index signé Ed25519, installation par la CLI et le Store
**Statut** : accepté (2026-10-16)
**Contexte** : budget zéro (pas de signature de code payante), dépôt source privé, binaires publiés dans le dépôt public `kortex-releases`. Il faut que l'installation d'un outil soit sûre même si l'hébergement des binaires (GitHub) ou le réseau sont hostiles.
**Décision** :
- **Paquet** = `tar.gz` contenant exactement `manifest.json` (id, version, cible, nom du binaire, SHA-256 du binaire) et le binaire autonome de l'outil (`kortex-<id>[.exe]`, application Dioxus desktop, CSS embarqué, aucun `dx` requis). Mêmes paquets pour la CLI (`id = cli`), le Store (`apps.store`) et chaque outil.
- **Index** `index.json` (+ `index.json.sig`) : pour chaque artefact, URL, taille et SHA-256 ; **signé Ed25519** sur les octets exacts du fichier. La clé publique est compilée dans les clients (`crates/kortex-catalog/release.pub`) ; la clé privée n'existe que dans le secret CI `KORTEX_SIGNING_KEY` et une copie locale hors dépôt.
- **Vérification côté client** (`kortex-pkg`) : signature de l'index → taille et SHA-256 de l'artefact → extraction par **liste blanche** (seuls `manifest.json` et le binaire attendu, fichiers réguliers, tailles plafonnées ; liens, `../`, chemins absolus, doublons refusés) → cohérence manifest/index (id, version, plateforme) → SHA-256 du binaire. Installation dans un dossier d'attente puis `rename` ; registre écrit de façon atomique ; échec = rien d'installé. Les anciennes versions ne sont supprimées qu'après succès.
- **HTTP** : `https://` uniquement (et `http://localhost` pour le développement) ; lectures plafonnées en taille.
- **Pas de quarantaine macOS** pour ce qu'installe la CLI/le Store (téléchargement hors navigateur) ; signature **ad hoc** (`codesign -s -`) faite par la CI ; une vraie signature pourra être ajoutée plus tard dans la même étape.
- `install.sh` / `install.ps1` : récupèrent la CLI via `cli-latest.txt` (même dossier que l'index, servi par kortex.site) et vérifient son SHA-256. Chaîne de confiance : TLS vers kortex.site pour ce premier binaire, puis signature Ed25519 pour tout le reste.
**Alternatives** : minisign/cosign (outil externe à installer), TUF (complet mais lourd), signature par paquet (l'index signé suffit et permet de révoquer en republiant).
**Conséquences** : compromettre GitHub ne permet pas de faire installer un binaire modifié sans la clé privée ; compromettre le secret CI le permettrait → à protéger (environnement protégé, rotation avec `xtask keygen`, qui impose de republier les clients). Pas de protection contre le retour à une ancienne version signée (rollback) tant que l'index n'a pas de numéro de séquence : à ajouter.
