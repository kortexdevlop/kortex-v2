# 0033 — Cookie de préférences d'affichage partagé
**Statut** : accepté (2026-10-20), demande de l'utilisateur (« un cookie qui garde le style de la page, et d'autres options simples et très utiles »).
**Constat** : le thème et le mode étaient gardés dans `localStorage`, séparé pour chaque adresse : choisir « sombre » sur kortex.site ne se retrouvait pas sur flow.kortex.site ni dans les outils (autre origine).
**Décision** :
- Un seul cookie `k-prefs`, `Domain=kortex.site`, `Path=/`, `SameSite=Lax`, `Secure` en HTTPS, `Max-Age` 1 an, **non HttpOnly** (le site, les apps et les outils le lisent). Contenu : `t` (thème `light|dark`), `m` (mode `simple|medium|pro`), `s` (taille du texte `large`), valeurs validées à la lecture ; une valeur par défaut est retirée, un cookie vide est supprimé.
- **Écrit uniquement après un choix explicite** (jamais à l'ouverture d'une page). Aucune donnée personnelle, aucun identifiant, aucun suivi ; lien « Réinitialiser mes préférences » en pied de page. La page de confidentialité le mentionne (le cookie de session de l'API reste séparé, limité à `api.kortex.site`).
- Taille du texte : `html[data-size="large"] { font-size: 112.5% }` dans `design/components.css` (tout est en `rem`). Elle est transmise aux outils par le message `kortex:init` existant (champ `size`, ignoré s'il est absent), comme le thème et le mode.
- Code : `kortex-platform::document::{shared_get, shared_set, shared_clear, apply_size}` (cookie sur le web, magasin de préférences `shared` en natif, aucun cookie sur desktop) ; `kortex-shell::use_appearance` lit le cookie avant sa copie locale et n'écrit qu'après un choix ; site : `window.kortexPrefs` (script de l'en-tête de `Base.astro`).
- Repli : `localStorage` (`k-theme`, `k-mode`) est encore écrit et lu si les cookies sont bloqués.
**Conséquences et limites** : le cookie est envoyé aux requêtes de tous les sous-domaines, dont `api.` et `run.` (quelques octets, sans valeur sensible). Il est lisible par les scripts de l'origine des outils ; il ne contient que ces trois réglages. « Réinitialiser » vide le cookie mais pas la copie locale propre à chaque application (repli).
**Alternatives** : cookie de session du navigateur (écarté : il disparaît à la fermeture, donc ne « garde » rien) ; synchronisation par le compte (écarté : exige une connexion pour un simple réglage d'affichage) ; langue dans le cookie (écarté pour l'instant : la langue est portée par l'URL).
